# Zynq PL 数据直写 PS DDR 的环形缓存机制

在 Zynq 数据采集系统中，PL 产生的数据通常需要送入 PS DDR，再由 ARM 软件读取和处理。这里真正需要解决的问题不是一次 AXI 写操作，而是如何让 PL 连续写入、PS 独立读取，同时避免双方访问同一帧。

本文介绍 PL 数据经过 FIFO 和 DMA 写入 PS DDR Ring Buffer 的完整机制。文章不逐行展开源码和软件驱动，重点说明整体架构、三个 FPGA 模块的分工、DDR 地址划分、写地址推进以及 PS 读取规则。相关 RTL、HLS 源码和 testbench 作为文章附件提供。

## 1 整体架构

<p align="center">
  <img src="./Images/Ring_Buffer_Architecture.png" alt="PL 数据直写 PS DDR 环形缓存架构" width="1000">
</p>

整条链路可以概括为：

`PL 报文 → AXI4-Stream FIFO → DMA → AXI HP 接口 → PS DDR Ring Buffer → PS 软件`

各模块的职责如下。

| 模块 | 主要作用 |
| --- | --- |
| PL 报文模块 | 按既定格式连续输出 32 bit 数据流 |
| FIFO | 完成时钟域隔离，并吸收 DMA 和 AXI 总线的短时回压 |
| DMA 控制模块 | 配置本帧的 DDR 写地址和搬运长度，启动 DMA，并在完成后推进写地址 |
| DMA | 将 AXI4-Stream 数据转换为 AXI4 Memory-Mapped 写事务 |
| AXI HP 接口 | 为 PL 主设备提供访问 PS DDR 的高带宽通道 |
| DDR Ring Buffer | 按固定大小的帧槽循环保存数据 |
| PS 软件 | 读取 PL 提供的写地址，避开正在写入的帧，处理已经完成的帧 |

## 2 FPGA 模块实现

<p align="center">
  <img src="./Images/DMA_Module_Connection.png" alt="DMA 内部模块连接关系" width="800">
</p>

图中的 DMA 子系统由 `DMA_CTRL`、`PL2PS_DMA` 和 `DMA_axi_reg_S` 三部分组成。写指针的生成、数据搬运以及 PS 侧读取接口分别由不同模块完成。

### 2.1 DMA_CTRL：启动 DMA 并推进写指针

[DMA_CTRL.v](./Code/Vivado/DMA_CTRL/DMA_CTRL.v) 是环形写入的控制模块，主要输出：

- `PL2PS_DMA_Start`：连接 HLS DMA 的 `ap_start`；
- `axiOut_Offset`：本次 DMA 写入的 DDR 帧槽起始地址；
- `DataLength`：本次搬运的 32 bit 数据数量。

复位解除后，`PL2PS_DMA_Start` 持续为高，使 HLS DMA 在一次搬运完成并重新就绪后继续启动下一次搬运。`axiOut_Offset` 在本帧搬运期间保持不变；收到单周期的 `PL2PS_DMA_Done` 后，地址增加 `0x1_0000`。当前地址等于 `LAST_ADDR` 时，下一个地址回到 `FIRST_ADDR`。

`DataLength` 的单位不是 Byte，而是 32 bit word。模块通过 `DATA_SIZE / 4` 得到该数值。例如一帧为 32,848 Bytes 时，`DataLength` 应为 8,212。

配套的 [tb_DMA_CTRL.v](./Code/Vivado/DMA_CTRL/tb_DMA_CTRL.v) 用周期性单脉冲模拟 DMA 完成信号，可用于观察地址递增过程。

### 2.2 PL2PS_DMA：完成 FIFO 到 DDR 的搬运

[pl2ps_dma.cpp](./Code/HLS/PL2PS_DMA/pl2ps_dma.cpp) 和 [pl2ps_dma.h](./Code/HLS/PL2PS_DMA/pl2ps_dma.h) 是 HLS DMA 的源文件。模块的输入为 32 bit AXI4-Stream，输出为 AXI4 Master 写接口，目标地址通过 `offset=direct` 方式由 `axiOut_Offset` 提供。

一次启动后，模块循环执行 `DataLength` 次：每次从 FIFO 读取一个 32 bit 数据，再写入连续的 DDR 地址。循环采用 `II=1` 流水，AXI 最大写突发长度配置为 32 beat，即一个完整突发最多搬运 128 Bytes。

该 AXI4-Stream 接口没有使用 `TLAST` 判断帧结束，整帧长度完全由 `DataLength` 决定。如果 FIFO 暂时没有数据，HLS DMA 会阻塞等待；只有指定数量的数据全部写入后，`ap_done` 才会置位。

配套的 [tb_pl2ps_dma.cpp](./Code/HLS/PL2PS_DMA/tb_pl2ps_dma.cpp) 对多种长度进行测试，同时检查指定长度之后的 DDR 空间没有被额外改写。

### 2.3 DMA_axi_reg_S：向 PS 提供写指针

[DMA_axi_reg_S.v](./Code/Vivado/DMA_axi_reg_S/DMA_axi_reg_S.v) 是 AXI4-Lite 从设备。写指针并不是在该模块内部累加，而是由 `DMA_CTRL` 的 `axiOut_Offset` 产生，再通过输入端口 `axiOut_Pointer` 接入寄存器模块。

PS 读取寄存器基地址偏移 `0x00` 时，返回当前 `axiOut_Pointer`。在本文对应的系统地址分配中，寄存器基地址为 `0x83C0_0000`，因此 PS 通过读取 `0x83C0_0000` 获得当前环形写地址。该地址是 DDR 物理地址，而不是 PS 的虚拟地址或帧索引。

从功能上看，`DMA_CTRL` 负责维护和更新写指针，`DMA_axi_reg_S` 负责把写指针作为只读状态提供给 PS。寄存器模块本身没有读指针、满空判断或覆盖保护。

## 3 DDR Ring Buffer 的地址划分

当前设计在 PS DDR 中为环形缓存预留 32 MiB 地址空间：

| 参数 | 当前设置 |
| --- | --- |
| Ring Buffer 起始地址 | `0x3E00_0000` |
| Ring Buffer 结束地址 | `0x4000_0000`，不包含该地址 |
| 帧槽数量 | 512 |
| 单个帧槽大小 | `0x1_0000` Bytes，即 65,536 Bytes |
| 最后一个帧槽起始地址 | `0x3FFF_0000` |
| 当前 V2 报文有效长度 | 32,848 Bytes |

本文按照 Word 架构图中的 512 帧配置说明。附件 [DMA_CTRL.v](./Code/Vivado/DMA_CTRL/DMA_CTRL.v) 的默认参数为 `FIRST_ADDR=0x3E00_0000`、`LAST_ADDR=0x3FFF_0000`、`DATA_SIZE=32848`，与本文的地址规划和 V2 报文长度一致。由此得到的 `DataLength` 为 8,212 个 32 bit word。

第 n 帧槽的起始地址为：

`frame_addr(n) = 0x3E00_0000 + n × 0x1_0000，n = 0～511`

因此，前几个帧槽和最后一个帧槽分别为：

| 帧槽 | 起始地址 |
| --- | --- |
| 第 1 帧 | `0x3E00_0000` |
| 第 2 帧 | `0x3E01_0000` |
| 第 3 帧 | `0x3E02_0000` |
| 第 4 帧 | `0x3E03_0000` |
| … | … |
| 第 512 帧 | `0x3FFF_0000` |

每个槽固定预留 64 KiB，而当前一帧有效报文为 32,848 Bytes。DMA 每次搬运一个完整报文，下一帧地址仍按 64 KiB 的固定步长递增。这样虽然每个槽内存在预留空间，但地址计算简单，PS 也能通过帧号直接定位数据。

当第 512 帧槽写完后，下一个目标地址不再继续增加，而是回到 `0x3E00_0000`。这就是 Ring Buffer 的地址回卷。它保存的是最近一段时间内的数据，而不是无限增长的数据文件。

## 4 PL 侧如何写入一帧

PL 侧一次完整写入可分为以下步骤。

### 4.1 数据先进入 FIFO

报文模块以 32 bit AXI4-Stream 形式输出数据。FIFO 的输入侧连接 PL 数据时钟域，输出侧连接 DMA 时钟域。DMA 或 AXI 总线短时间产生回压时，新到的数据先暂存在 FIFO 中。

### 4.2 DMA 控制模块给出本帧参数

DMA 控制模块保存当前环形写地址，并在一帧开始前向 DMA 提供：

- 本帧 DDR 目标地址；
- 本帧搬运长度；
- DMA 启动控制信号。

按当前 V2 报文配置时，目标地址是当前 64 KiB 帧槽的起始地址，有效报文长度为 32,848 Bytes。

### 4.3 DMA 将数据写入 Ring Buffer

DMA 从 FIFO 接收 AXI4-Stream 数据，将其转换为 AXI 写事务，并通过 Zynq 的 AXI HP 接口写入 PS DDR。整个搬运过程由 PL 侧控制，PS 不需要逐字接收数据。

### 4.4 搬运完成后推进写地址

DMA 完成当前帧的全部写事务后，DMA 控制模块再将写地址增加 `0x1_0000`。如果当前写的是最后一个帧槽，则把下一帧地址重新设置为 `0x3E00_0000`。

这里的顺序不能颠倒：必须先确认当前帧已经完整写入 DDR，再推进写地址。否则 PS 可能把尚未写完的帧误认为有效数据。

## 5 写地址的含义

PS 可以通过映射在物理地址 `0x83C0_0000` 的寄存器读取 PL 当前写地址。本文将该寄存器定义为“当前写入槽或下一待写槽的起始地址”，也就是 PS 必须避开的帧槽。

`axiOut_Offset` 本身是 `DMA_CTRL` 中的寄存器，只在复位或 `PL2PS_DMA_Done` 到来时更新，因此在整帧 DMA 搬运期间保持稳定。`DMA_axi_reg_S` 在 AXI4-Lite 读事务成立时对该值进行采样。PS 应通过轮询观察写指针变化；一次刚好发生在 DMA 完成边界的读取可能仍得到更新前的地址，下一次读取才会看到新地址。

写地址的推进关系如下：

1. 系统初始化后，写地址指向第 1 帧槽 `0x3E00_0000`；
2. DMA 使用该地址写入第 1 帧，写入过程中地址保持不变；
3. 第 1 帧完成后，写地址推进到 `0x3E01_0000`；
4. 写地址一旦离开第 1 帧槽，第 1 帧才对 PS 可见；
5. 第 512 帧完成后，写地址回到第 1 帧槽。

因此，写地址不是“最后一帧完成地址”。它指向的是当前禁止 PS 读取的位置，写地址的前一个槽才是最近完成的帧。

如果实际寄存器采用“最后完成帧地址”的定义，PS 端算法也必须同步改变。两种定义都能实现，但 PL 和 PS 必须统一，不能在同一设计中混用。

## 6 PS 侧如何安全读取

如果 PS 只需要读取最新一帧，可以先读取当前写地址，再将其回退一个帧槽：

`latest_addr = current_write_addr - 0x1_0000`

当当前写地址为 Ring Buffer 起始地址时，回退结果应回卷到 `0x3FFF_0000`。

如果 PS 需要按顺序处理所有帧，则应在软件中维护独立的读位置。基本过程如下：

1. PS 读取并保存当前写地址；
2. 如果软件读地址等于当前写地址，说明没有新的安全帧可读；
3. 如果两者不同，PS 读取软件读地址对应的完整帧；
4. 处理完成后，软件读地址增加 `0x1_0000`；
5. 读到最后一个槽后，软件读地址同样回到起始地址；
6. 重复读取新的 PL 写地址，继续判断是否有可读帧。

PS 读取 DDR 时还需要注意 CPU Cache。如果该 DDR 区域采用可缓存映射，应在读取 PL 新写入的数据前执行正确的 Cache 失效操作；也可以将这段预留内存映射为不可缓存区域。

## 7 回卷与数据覆盖

当前结构中，PL 写入不等待 PS 确认。即使 PS 处理速度变慢，PL 仍会按固定顺序循环写入 512 个帧槽。当写地址绕行一圈后，最早的数据会被新数据覆盖。

这是一种“采集不中断、允许覆盖旧数据”的设计：

- 优点是 PS 软件不会反向阻塞 PL 数据链路；
- 代价是 PS 必须在 PL 再次写到同一帧槽前完成读取；
- 仅凭一个循环地址，无法区分“暂无新数据”和“PL 已经完整绕行一圈”。

当前报文中包含从 0 开始递增的帧序号，PS 可以用它检查数据是否连续。如果读到的帧序号发生跳变，说明中间可能出现丢帧或旧数据已被覆盖。若系统要求严格区分空、满和覆盖状态，还可以额外提供单调递增的写入计数器。

需要注意，512 个帧槽中有 1 个槽始终被视为当前写入位置。在只使用读写地址判空、且不允许读写指针重合歧义的情况下，稳定运行时最多同时保留 511 个已完成但尚未读取的帧。

## 8 DMA 带宽与链路余量

<p align="center">
  <img src="./Images/DMA_Bandwidth_ILA.png" alt="DMA AXI 写通道 ILA 波形" width="1000">
</p>

图中 `wvalid` 持续有效，`wready` 在一次 32 beat 突发写入期间保持为高；突发结束后，`wready` 拉低约 3 个时钟周期，随后开始下一次突发传输。`wlast` 在每个突发的最后一个数据拍置位。红色标注分别对应 32 个有效传输周期和约 3 个回压周期。

文档中的测试条件为：DMA 时钟 200 MHz、AXI 数据宽度 32 bit，每次突发写入 32 beat，突发之间约有 3 个时钟周期回压。平均带宽可估算为：

`32 × 4 Bytes ÷ (32 + 3) × 200 MHz ≈ 731 MB/s`

该结果说明，在当前测试条件下，DMA 和 AXI HP 通道能够提供较高的写入带宽。实际设计仍应根据报文产生速率检查长期平均带宽，并根据最坏回压时间设置 FIFO 深度。FIFO 溢出、DMA 超时和 AXI 写错误也应作为状态上报给 PS。

## 9 实现时需要统一的关键参数

| 项目 | 需要统一的内容 |
| --- | --- |
| DDR 预留区域 | Linux、裸机程序和 PL 必须共同使用 `0x3E00_0000～0x3FFF_FFFF`，且不得分配给其他用途 |
| 帧槽步长 | PL 与 PS 均按 64 KiB 计算下一帧地址 |
| 有效报文长度 | 当前 V2 报文为 32,848 Bytes，PS 不应把槽内剩余空间当作有效数据 |
| 写地址语义 | 明确它表示当前写入槽，而不是最后完成槽 |
| 地址发布方式 | `DMA_CTRL` 在完成边界更新地址，`DMA_axi_reg_S` 通过偏移 `0x00` 提供给 PS 轮询读取 |
| 完成条件 | 只有 DMA 完成并确认本帧写入结束后，才能推进写地址 |
| 回卷规则 | `0x3FFF_0000` 的下一帧地址回到 `0x3E00_0000` |
| Cache 属性 | PS 读取前进行 Cache 失效，或使用不可缓存映射 |
| 连续性检查 | 使用报文帧序号检查丢帧和覆盖 |

## 10 总结

只使用 Ring Buffer 后，PL 到 PS DDR 的数据路径更加直接：

- FIFO 处理跨时钟域和短时间 AXI 回压；
- DMA 把每帧数据直接写入 DDR 环形缓存；
- DMA 控制模块负责生成写地址，并在一帧完成后推进地址；
- PS 通过写地址避开当前写入槽，并用自己的读位置顺序消费完整帧；
- 写地址到达末尾后回到起始地址，未及时读取的旧数据会被覆盖。

整套机制可以概括为一句话：PL 先把一帧完整写入 DDR，再推进环形写地址；PS 始终避开当前写地址，并在写指针再次绕回之前完成读取。
