# Ring-Buffer Mechanism for Directly Writing Zynq PL Data to PS DDR

In a Zynq data-acquisition system, data generated by the PL usually needs to be transferred to PS DDR and then read and processed by ARM software. The real problem is not how to perform a single AXI write, but how to let the PL write continuously while the PS reads independently, without allowing both sides to access the same frame.

This article describes the complete mechanism for writing PL data through a FIFO and DMA into a PS DDR Ring Buffer. Rather than explaining the source code and software driver line by line, it focuses on the overall architecture, the responsibilities of the three FPGA modules, DDR address allocation, write-address advancement, and the PS read rules. The related RTL, HLS source code, and testbenches are provided as attachments to the article.

## 1 Overall Architecture

<p align="center">
  <img src="./Images/Ring_Buffer_Architecture.png" alt="Ring-buffer architecture for directly writing PL data to PS DDR" width="1000">
</p>

The complete data path can be summarized as:

`PL packet → AXI4-Stream FIFO → DMA → AXI HP interface → PS DDR Ring Buffer → PS software`

The responsibilities of each module are listed below.

| Module | Primary responsibility |
| --- | --- |
| PL packet module | Continuously outputs a 32-bit data stream in the defined format |
| FIFO | Provides clock-domain isolation and absorbs short periods of backpressure from the DMA and AXI bus |
| DMA control module | Configures the DDR write address and transfer length for the current frame, starts the DMA, and advances the write address after completion |
| DMA | Converts AXI4-Stream data into AXI4 Memory-Mapped write transactions |
| AXI HP interface | Provides a high-bandwidth channel through which PL masters access PS DDR |
| DDR Ring Buffer | Stores data cyclically in fixed-size frame slots |
| PS software | Reads the write address supplied by the PL, avoids the frame currently being written, and processes completed frames |

## 2 FPGA Module Implementation

<p align="center">
  <img src="./Images/DMA_Module_Connection.png" alt="Internal connections among the DMA modules" width="800">
</p>

The DMA subsystem in the diagram consists of `DMA_CTRL`, `PL2PS_DMA`, and `DMA_axi_reg_S`. Write-pointer generation, data transfer, and the PS-side read interface are handled by separate modules.

### 2.1 DMA_CTRL: Starting the DMA and Advancing the Write Pointer

[DMA_CTRL.v](./Code/Vivado/DMA_CTRL/DMA_CTRL.v) is the control module for cyclic writes. Its main outputs are:

- `PL2PS_DMA_Start`: connected to `ap_start` of the HLS DMA;
- `axiOut_Offset`: start address of the DDR frame slot for the current DMA transfer;
- `DataLength`: number of 32-bit data words transferred in the current operation.

After reset is released, `PL2PS_DMA_Start` remains high so that the HLS DMA starts the next transfer after the current one completes and the DMA becomes ready again. `axiOut_Offset` remains unchanged throughout the current frame transfer. When the single-cycle `PL2PS_DMA_Done` pulse is received, the address increases by `0x1_0000`. If the current address equals `LAST_ADDR`, the next address wraps to `FIRST_ADDR`.

The unit of `DataLength` is not Byte, but a 32-bit word. The module obtains this value through `DATA_SIZE / 4`. For example, when one frame is 32,848 Bytes, `DataLength` should be 8,212.

The accompanying [tb_DMA_CTRL.v](./Code/Vivado/DMA_CTRL/tb_DMA_CTRL.v) uses periodic single-cycle pulses to emulate the DMA completion signal and can be used to observe the address-increment process.

### 2.2 PL2PS_DMA: Transferring Data from the FIFO to DDR

[pl2ps_dma.cpp](./Code/HLS/PL2PS_DMA/pl2ps_dma.cpp) and [pl2ps_dma.h](./Code/HLS/PL2PS_DMA/pl2ps_dma.h) are the source files for the HLS DMA. The module input is a 32-bit AXI4-Stream interface, and the output is an AXI4 Master write interface. The target address is supplied by `axiOut_Offset` using `offset=direct`.

After one start, the module loops `DataLength` times. On each iteration, it reads one 32-bit value from the FIFO and writes it to a consecutive DDR address. The loop is pipelined with `II=1`, and the maximum AXI write-burst length is configured as 32 beat, so one complete burst can transfer up to 128 Bytes.

This AXI4-Stream interface does not use `TLAST` to determine the end of a frame. The entire frame length is determined solely by `DataLength`. If the FIFO temporarily has no data, the HLS DMA blocks and waits. `ap_done` is asserted only after all of the specified data has been written.

The accompanying [tb_pl2ps_dma.cpp](./Code/HLS/PL2PS_DMA/tb_pl2ps_dma.cpp) tests multiple lengths and also checks that the DDR space beyond the specified length is not modified.

### 2.3 DMA_axi_reg_S: Providing the Write Pointer to the PS

[DMA_axi_reg_S.v](./Code/Vivado/DMA_axi_reg_S/DMA_axi_reg_S.v) is an AXI4-Lite slave. The write pointer is not incremented inside this module. Instead, it is generated as `axiOut_Offset` by `DMA_CTRL` and connected to the register module through the `axiOut_Pointer` input port.

When the PS reads offset `0x00` from the register base address, the current `axiOut_Pointer` is returned. In the system address map used by this article, the register base address is `0x83C0_0000`, so the PS obtains the current ring-buffer write address by reading `0x83C0_0000`. This address is a DDR physical address, not a PS virtual address or a frame index.

Functionally, `DMA_CTRL` maintains and updates the write pointer, while `DMA_axi_reg_S` exposes the write pointer to the PS as read-only status. The register module itself does not contain a read pointer, empty/full detection, or overwrite protection.

## 3 DDR Ring Buffer Address Allocation

The current design reserves a 32 MiB address range in PS DDR for the ring buffer:

| Parameter | Current setting |
| --- | --- |
| Ring Buffer start address | `0x3E00_0000` |
| Ring Buffer end address | `0x4000_0000`, excluding this address |
| Number of frame slots | 512 |
| Size of each frame slot | `0x1_0000` Bytes, or 65,536 Bytes |
| Start address of the last frame slot | `0x3FFF_0000` |
| Current valid V2 packet length | 32,848 Bytes |

This article follows the 512-frame configuration shown in the Word architecture diagram. The default parameters in the attached [DMA_CTRL.v](./Code/Vivado/DMA_CTRL/DMA_CTRL.v) are `FIRST_ADDR=0x3E00_0000`, `LAST_ADDR=0x3FFF_0000`, and `DATA_SIZE=32848`, which match the address plan and V2 packet length described here. The resulting `DataLength` is 8,212 32-bit words.

The start address of frame slot n is:

`frame_addr(n) = 0x3E00_0000 + n × 0x1_0000，n = 0～511`

Therefore, the first few frame slots and the final frame slot are:

| Frame slot | Start address |
| --- | --- |
| Frame 1 | `0x3E00_0000` |
| Frame 2 | `0x3E01_0000` |
| Frame 3 | `0x3E02_0000` |
| Frame 4 | `0x3E03_0000` |
| … | … |
| Frame 512 | `0x3FFF_0000` |

Each slot reserves a fixed 64 KiB, while the valid packet in the current design is 32,848 Bytes. The DMA transfers one complete packet at a time, and the address for the next frame still advances by the fixed 64 KiB stride. Although this leaves unused reserved space in each slot, it simplifies address calculation and allows the PS to locate data directly from the frame number.

After the 512th frame slot has been written, the next target address does not continue increasing; instead, it returns to `0x3E00_0000`. This is the Ring Buffer address wraparound. The buffer retains data from only the most recent time interval rather than behaving like an infinitely growing data file.

## 4 How the PL Writes One Frame

One complete PL-side write can be divided into the following steps.

### 4.1 Data First Enters the FIFO

The packet module outputs data as a 32-bit AXI4-Stream. The FIFO input side is connected to the PL data clock domain, while its output side is connected to the DMA clock domain. When the DMA or AXI bus briefly applies backpressure, newly arriving data is temporarily stored in the FIFO.

### 4.2 The DMA Control Module Supplies the Current Frame Parameters

The DMA control module stores the current ring-buffer write address and supplies the following to the DMA before a frame begins:

- DDR target address for the current frame;
- transfer length for the current frame;
- DMA start control signal.

With the current V2 packet configuration, the target address is the start of the current 64 KiB frame slot, and the valid packet length is 32,848 Bytes.

### 4.3 The DMA Writes Data into the Ring Buffer

The DMA receives AXI4-Stream data from the FIFO, converts it into AXI write transactions, and writes it into PS DDR through the Zynq AXI HP interface. The entire transfer is controlled by the PL side; the PS does not need to receive the data word by word.

### 4.4 The Write Address Advances After the Transfer Completes

After the DMA completes all write transactions for the current frame, the DMA control module increments the write address by `0x1_0000`. If the current frame was written into the last frame slot, the next frame address is reset to `0x3E00_0000`.

This order must not be reversed: the current frame must first be confirmed as fully written to DDR, and only then may the write address advance. Otherwise, the PS may treat a frame that is still being written as valid.

## 5 Meaning of the Write Address

The PS can read the current PL write address from the register mapped at physical address `0x83C0_0000`. This article defines that register as “the start address of the frame slot currently being written or the next frame slot to be written,” meaning that it is the frame slot the PS must avoid.

`axiOut_Offset` itself is a register in `DMA_CTRL`. It is updated only on reset or when `PL2PS_DMA_Done` arrives, so it remains stable throughout a complete DMA frame transfer. `DMA_axi_reg_S` samples this value when an AXI4-Lite read transaction occurs. The PS should monitor changes in the write pointer by polling. A read that happens exactly at the DMA-completion boundary may still return the previous address; the next read will then observe the new address.

The write address advances as follows:

1. After system initialization, the write address points to the first frame slot, `0x3E00_0000`.
2. The DMA uses this address to write frame 1, and the address remains unchanged during the write.
3. After frame 1 completes, the write address advances to `0x3E01_0000`.
4. Frame 1 becomes visible to the PS only after the write address leaves the first frame slot.
5. After frame 512 completes, the write address wraps to the first frame slot.

Therefore, the write address is not the “address of the last completed frame.” It points to the location that the PS is currently prohibited from reading; the slot immediately before the write address is the most recently completed frame.

If the actual register instead uses the semantics “address of the last completed frame,” the PS-side algorithm must be changed accordingly. Both definitions can work, but the PL and PS must use the same definition and must not mix the two within one design.

## 6 How the PS Reads Safely

If the PS only needs the latest frame, it can first read the current write address and then move back by one frame slot:

`latest_addr = current_write_addr - 0x1_0000`

When the current write address is the Ring Buffer start address, the result must wrap to `0x3FFF_0000`.

If the PS needs to process all frames in order, the software should maintain an independent read position. The basic procedure is:

1. The PS reads and stores the current write address.
2. If the software read address equals the current write address, there is no new safe frame to read.
3. If the two addresses differ, the PS reads the complete frame at the software read address.
4. After processing completes, the software read address increases by `0x1_0000`.
5. After the last slot is read, the software read address likewise wraps to the start address.
6. The PS repeatedly reads the new PL write address and continues checking whether a readable frame is available.

CPU Cache handling also requires attention when the PS reads DDR. If this DDR region uses a cacheable mapping, the correct Cache invalidation operation must be performed before reading data newly written by the PL. Alternatively, the reserved memory region can be mapped as non-cacheable.

## 7 Wraparound and Data Overwrite

In the current architecture, PL writes do not wait for PS acknowledgement. Even if PS processing slows down, the PL continues writing cyclically through the 512 frame slots in a fixed order. After the write address completes one full cycle, the oldest data is overwritten by new data.

This design favors uninterrupted acquisition while allowing old data to be overwritten:

- The advantage is that PS software does not backpressure the PL data path.
- The cost is that the PS must finish reading a frame before the PL writes to the same frame slot again.
- A single cyclic address cannot distinguish between “no new data” and “the PL has completed an entire wraparound.”

The current packet contains a frame sequence number that increments from zero, which the PS can use to check data continuity. If the observed frame sequence number jumps, frames may have been dropped or old data may have been overwritten. If the system must strictly distinguish empty, full, and overwrite conditions, an additional monotonically increasing write counter can be provided.

Note that one of the 512 frame slots is always treated as the current write position. When only the read and write addresses are used to detect empty status, and ambiguity caused by identical read and write pointers is not permitted, stable operation can retain at most 511 completed but unread frames at the same time.

## 8 DMA Bandwidth and Link Margin

<p align="center">
  <img src="./Images/DMA_Bandwidth_ILA.png" alt="ILA waveform of the DMA AXI write channel" width="1000">
</p>

In the waveform, `wvalid` remains asserted, while `wready` stays high throughout one 32-beat burst write. After the burst ends, `wready` is deasserted for approximately three clock cycles before the next burst begins. `wlast` is asserted on the final data beat of each burst. The red annotations respectively indicate 32 valid transfer cycles and approximately three backpressure cycles.

The test conditions documented here are a 200 MHz DMA clock, a 32-bit AXI data width, 32 beats per burst write, and approximately three clock cycles of backpressure between bursts. The average bandwidth can be estimated as:

`32 × 4 Bytes ÷ (32 + 3) × 200 MHz ≈ 731 MB/s`

This result indicates that, under the current test conditions, the DMA and AXI HP channel can provide high write bandwidth. A practical design should still check the long-term average bandwidth against the packet-generation rate and size the FIFO for the worst-case backpressure duration. FIFO overflow, DMA timeout, and AXI write errors should also be reported to the PS as status.

## 9 Key Parameters That Must Be Consistent During Implementation

| Item | Required consistency |
| --- | --- |
| Reserved DDR region | Linux, bare-metal software, and the PL must all use `0x3E00_0000～0x3FFF_FFFF`, and the range must not be allocated for any other purpose |
| Frame-slot stride | Both the PL and PS calculate the next frame address using 64 KiB |
| Valid packet length | The current V2 packet is 32,848 Bytes; the PS must not treat the remaining space in a slot as valid data |
| Write-address semantics | Clearly define that it represents the current write slot, not the last completed slot |
| Address publication method | `DMA_CTRL` updates the address at the completion boundary, and `DMA_axi_reg_S` makes it available for PS polling at offset `0x00` |
| Completion condition | The write address may advance only after the DMA completes and confirms that the current frame write has finished |
| Wraparound rule | The frame address after `0x3FFF_0000` wraps to `0x3E00_0000` |
| Cache attributes | Invalidate the Cache before PS reads, or use a non-cacheable mapping |
| Continuity check | Use the packet frame sequence number to detect dropped frames and overwrites |

## 10 Summary

With the Ring Buffer in place, the data path from PL to PS DDR becomes more direct:

- The FIFO handles clock-domain crossing and short periods of AXI backpressure.
- The DMA writes each frame directly into the DDR ring buffer.
- The DMA control module generates the write address and advances it after a frame completes.
- The PS avoids the current write slot using the write address and consumes complete frames sequentially with its own read position.
- When the write address reaches the end, it returns to the start, and old data that was not read in time is overwritten.

The entire mechanism can be summarized in one sentence: the PL first writes one complete frame into DDR and then advances the ring-buffer write address; the PS always avoids the current write address and completes its reads before the write pointer wraps around again.
